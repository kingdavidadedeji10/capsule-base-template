# capsule-base-template

A production-ready Next.js 15 starter template with Tailwind CSS, shadcn/ui, and Supabase SSR authentication. Built as the foundation for apps generated by [Capsule AI](https://capsule.ai).

---

## What's included

- **Next.js 15** (App Router)
- **Tailwind CSS** with a dark-mode-friendly zinc/muted palette
- **shadcn/ui** components (Button, Card, Input, Label)
- **Supabase SSR** — server-side auth with automatic session refresh via middleware
- **Auth flow** — login, signup, sign out, and a protected dashboard page
- **Error & loading boundaries** — `error.tsx`, `loading.tsx`, `not-found.tsx`
- **Env validation** — fails loudly at startup if required variables are missing
- **GitHub Actions CI** — builds on every push/PR to `main`

---

## Prerequisites

- Node.js ≥ 20 (`.nvmrc` is provided — run `nvm use` to switch automatically)
- A [Supabase](https://supabase.com) project (free tier is fine)

---

## Setup

1. **Clone the repo**

   ```bash
   git clone https://github.com/your-org/your-app.git
   cd your-app
   ```

2. **Install dependencies**

   ```bash
   npm install
   ```

3. **Configure environment variables**

   ```bash
   cp .env.local.example .env.local
   ```

   Open `.env.local` and fill in your Supabase project URL and anon key. Find them at:
   **Supabase Dashboard → Your Project → Settings → API**

4. **Start the dev server**

   ```bash
   npm run dev
   ```

   Open [http://localhost:3000](http://localhost:3000).

## Folder structure

```
app/
  (auth)/
    layout.tsx          ← centered layout for auth pages
    login/page.tsx      ← sign-in form
    signup/page.tsx     ← sign-up form
  api/auth/signout/
    route.ts            ← POST handler to sign out
  dashboard/
    page.tsx            ← protected page (redirects to /login if unauthenticated)
  error.tsx             ← global error boundary
  globals.css           ← Tailwind base styles + CSS variables
  layout.tsx            ← root layout with Geist font
  loading.tsx           ← global loading spinner
  not-found.tsx         ← 404 page
  page.tsx              ← landing page
lib/
  env.ts                ← fail-fast env validation
  supabase/
    client.ts           ← browser Supabase client
    server.ts           ← server Supabase client (cookies)
  utils.ts              ← cn() helper
components/
  ui/                   ← shadcn/ui components
middleware.ts           ← Supabase session refresh on every request
```

## Auth flow

| Route | Description |
|---|---|
| `/login` | Email + password sign-in → redirects to `/dashboard` |
| `/signup` | Email + password sign-up → shows email confirmation message |
| `/dashboard` | Protected — redirects to `/login` if no session |
| `POST /api/auth/signout` | Signs out and redirects to `/login` |

Session refresh is handled automatically by `middleware.ts` on every request, so server components always receive a valid session.

---

## How to extend

- Add new pages under `app/` — they automatically inherit the root layout and middleware
- Add new shadcn components with `npx shadcn@latest add <component>`
- Protect additional routes by calling `supabase.auth.getUser()` in the page's server component and redirecting if `user` is null
- Add Supabase database queries in server components using the `createClient()` from `lib/supabase/server`

## Deploy on Vercel

1. Push this repo to GitHub
2. Import it in [Vercel](https://vercel.com)
3. Add `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` as environment variables in the Vercel project settings
4. Deploy — Vercel will build and serve the app automatically
